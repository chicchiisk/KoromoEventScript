# Implementation Plan

- [x] 1. Foundation: `kes build` の CLI 契約と共有出力モデルを固める
- [x] 1.1 `kes build` の option parse と command line validation を公開仕様どおりに拡張する
  - `PROJECT_DIR` 省略時の project root 探索、`--entry`、`--target`、`--out-dir`、`--loc`、`--txt-il`、`--check-only`、`--warnings-as-errors`、`--log-format`、`--no-incremental` を保持できる options 境界を整える。
  - `windows` 以外の `--target`、値不足オプション、未知オプション、`--txt-il` と `--check-only` の同時指定を command line error として早期拒否する。
  - CLI 入口だけで build 実行可否が判断でき、無効な指定では終了コード `2` 相当の結果が観測できる状態にする。
  - *Requirements: 1.1, 1.5, 1.6, 1.7, 1.8*
- [x] 1.2 build 出力先の計画と artifact path モデルを整備する
  - project 既定の build path と `--out-dir` を統合し、基準言語は `events/`、ローカライズ言語は `events/loc/<language-tag>/` へ出力する規則を一元化する。
  - `.klib`、`.klibtxt`、`manifest.json` の相対位置を 1 つの planner から導けるようにする。
  - script ごとの出力先が planner の戻り値として確定し、後続タスクが path 判定ロジックを重複実装せずに済む状態にする。
  - *Requirements: 1.4, 3.2, 4.5, 4.7*
- [x] 1.3 manifest の最小ドキュメントモデルを定義する
  - entry `.kel`、入力 script 群、生成 `.klib` / `.klibtxt`、ローカライズ variant、target を保持できる manifest schema を実装する。
  - run / publish が後続で参照しやすいよう、build 結果から組み立てる責務境界を明確にする。
  - build 成功時に何を `manifest.json` へ残すかがコード上で表現され、writer 実装の受け皿が揃った状態にする。
  - *Requirements: 3.5*

- [x] 2. Core: build 前処理とパイプライン制御を完成させる
- [x] 2.1 `BuildPipelineService` の validation-only / normal build 分岐を実装する
  - `BuildPreparationService` を起点に、`kes.xml` 解決、entry `.kel` 解決、参照 `.kc` 解析、semantic 診断収集までを build pipeline へ集約する。
  - `--check-only` では書き戻しと成果物生成へ進まない制御を持たせ、warning-only success を返せるようにする。
  - build 実行モードごとに、準備済み document 群と diagnostics を一貫した result contract で受け取れる状態にする。
  - *Requirements: 1.2, 1.3, 2.1, 2.2, 2.4, 3.4, 5.2*
- [x] 2.2 normal build 向けのタグ補完書き戻しと失敗分類を統合する
  - `kes correct` と同じ tag assignment plan / rewrite service を normal build に差し込み、必要なときだけ `.kc` を更新してから compile へ進める。
  - syntax error、compile error、file I/O error を build pipeline 内で分類し、公開仕様の終了コードへ写像する。
  - normal build でのみ source rewrite が走り、失敗時は後続 artifact が生成されない状態にする。
  - *Requirements: 2.3, 2.5, 2.6, 2.7*

- [x] 3. Core: ローカライズと成果物生成を build パイプラインへ載せる
- [x] 3.1 (P) `--loc` 用のローカライズ辞書読み込みと text projection を実装する
  - project root 直下のローカライズ辞書 `.csv` を読み込み、指定言語列の存在、必要 tag の充足、翻訳テキストの取得を検証する。
  - `say` / `nar` / `select-case` の tag をキーに、compile-time 解決済みの localized document 群を返せるようにする。
  - `--loc <LOCALE>` 成功時だけ compiler が localized source を受け取り、辞書不在や列不在では build failure が観測できる状態にする。
  - *Requirements: 4.1, 4.2, 4.3, 4.4*
  - *Boundary: BuildLocalizationService, LocalizationDictionaryCsvRepository*
- [x] 3.2 (P) 基準言語とローカライズ言語の `.klib` / `.klibtxt` 出力を実装する
  - pipeline と output planner を使って、各 `.kc` に対応する `.klib` を基準言語または `loc/<language-tag>/` 配下へ書き出す。
  - `--txt-il` 指定時は同じ論理内容を持つ `.klibtxt` も対応パスへ生成し、`--check-only` では一切出力しない。
  - success build で出力ツリーに必要な `.klib` / `.klibtxt` が揃い、失敗時は部分的な成功扱いにならない状態にする。
  - *Requirements: 3.1, 3.2, 3.3, 3.4, 4.4, 4.5, 4.6*
  - *Boundary: BuildPipelineService, BuildOutputPlanner, KlibCompiler, KlibArtifactWriter*
  - *Depends: 1.2, 2.1, 3.1*
- [x] 3.3 (P) build 結果に対応した `manifest.json` の生成と保存を実装する
  - build で生成した script artifacts、entry、locale variants、target 情報から manifest document を組み立てて永続化する。
  - manifest の保存は artifact path 確定後の最後に 1 回だけ行い、保存失敗は file I/O error として build を失敗させる。
  - build 成功時に出力ルートへ `manifest.json` が存在し、内容が実際の artifact tree と一致する状態にする。
  - *Requirements: 2.7, 3.5*
  - *Boundary: BuildManifestWriter, BuildManifestDocument*
  - *Depends: 1.3, 3.2*

- [x] 4. Integration: command と diagnostics 契約を end-to-end で接続する
- [x] 4.1 `BuildCommand` / `BuildCheckOnlyCommand` を新しい pipeline へ接続する
  - normal build と validation-only build が同じ orchestration を共有しつつ、artifact emission gate だけ切り替えるようにする。
  - `--entry`、`--out-dir`、`--loc`、`--txt-il`、`--check-only` を command 層から pipeline request へ正しく受け渡す。
  - command 単体で success code `0`、warning-only check-only success、各 failure code の返却が観測できる状態にする。
  - *Requirements: 2.4, 3.4, 5.1, 5.2*
- [x] 4.2 CLI の diagnostics 出力契約と warnings-as-errors を仕上げる
  - `--warnings-as-errors` と `kes.xml` 設定を build pipeline の warning policy へ接続し、warning を終了コード `9` の失敗へ昇格できるようにする。
  - `--log-format json` と `text` の両方で diagnostics sink 出力を維持し、成功時は error diagnostic を出さないようにする。
  - 手元実行と CI の両方で、終了コードと stderr の契約だけで build 成否を機械判定できる状態にする。
  - *Requirements: 5.3, 5.4, 5.5, 5.6*

- [x] 5. Validation: `kes build` の公開仕様を自動テストで固定する
- [x] 5.1 (P) planner / localization / manifest のユニットテストを追加する
  - `--out-dir` あり / なし、基準言語 / locale path、locale `.csv` 不在、locale 列不在、manifest 内容の期待値を個別に固定する。
  - 共有 service ごとの入出力が単独で検証でき、path 規則と locale projection の回帰を局所テストで検知できる状態にする。
  - *Requirements: 1.4, 3.2, 3.5, 4.1, 4.2, 4.3, 4.5, 4.7*
  - *Boundary: BuildOutputPlanner, BuildLocalizationService, BuildManifestWriter*
- [x] 5.2 build command の統合テストで成果物生成フローを固定する
  - 基準言語 build、`--txt-il`、`--out-dir`、`--loc en`、`manifest.json` 生成、locale build failure を temporary project ベースで検証する。
  - 成功時の出力ツリーと失敗時の非生成条件が integration test で観測でき、`.klib` 出力契約の主要シナリオが網羅された状態にする。
  - *Requirements: 3.1, 3.2, 3.3, 3.5, 4.4, 4.5, 4.6*
- [x] 5.3 CLI / check-only の回帰テストで非破壊性と失敗コードを固定する
  - `build` の option parse、invalid combination、`--check-only` 非破壊、warning-only success、warnings-as-errors、syntax / compile / file error code を CLI 入口から確認する。
  - 利用者が `kes build` を直接叩いたときの戻り値と stderr 契約が、既存テストスイート上で再現できる状態にする。
  - *Requirements: 1.1, 1.6, 1.7, 1.8, 2.4, 2.5, 2.6, 2.7, 3.4, 5.1, 5.2, 5.3, 5.4, 5.5, 5.6*
