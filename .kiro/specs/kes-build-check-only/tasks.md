# Implementation Plan

- [x] 1. CLI実行基盤と検証フィクスチャを整える
- [x] 1.1 CLIプロセス入口と終了コード契約を実行可能にする
  - `kes` がプロセス引数を受け取り、CLIアプリケーションの結果をプロセス終了コードとして返せる状態にする。
  - コマンドラインエラー、構文エラー、ファイル入出力エラー、成功を表す終了コードが実装内で一貫して参照できるようにする。
  - 完了時には、テストからCLI呼び出し結果を整数の終了コードとして検証できる。
  - _Requirements: 1.1, 5.1, 5.2, 5.3, 5.4_

- [x] 1.2 標準診断出力の共有経路を用意する
  - 既存の診断フォーマットを使い、text と JSON Lines のどちらでも受け取った順序で診断を書き出せるようにする。
  - 診断が空の場合は、エラー診断も空行も出力しない。
  - 完了時には、同じ診断列を text と JSON Lines の両方でテストできる。
  - _Requirements: 4.1, 4.2, 4.3, 4.4, 4.5_

- [x] 1.3 check-only用のプロジェクト入力と成果物保護フィクスチャを整える
  - 成功、entry欠落、構文不正、成果物既存状態を確認できる最小プロジェクト入力を用意する。
  - build/dist や既存成果物が検査前後で変化していないことを比較できるテスト入力にする。
  - 完了時には、CLI統合テストが各プロジェクトケースをファイルとして参照できる。
  - _Requirements: 2.4, 3.3, 3.4, 3.5, 6.1, 6.2, 6.4_

- [x] 2. check-onlyを構成する独立サービスを実装する
- [x] 2.1 (P) `build --check-only` の引数受付とオプション検証を実装する
  - `build --check-only` と `build [PROJECT_DIR] --check-only` を有効なコマンド形として受け付ける。
  - `--project <DIR>` と `--log-format <text|json>` を解釈し、未対応コマンド、不正オプション、値不足、プロジェクト指定の重複をコマンドライン診断にする。
  - 不正引数ではプロジェクトファイルへアクセスせず、終了コード2を返す。
  - 完了時には、引数だけを変えた単体テストで有効形と不正形を判定できる。
  - _Requirements: 1.1, 1.2, 1.4, 4.2, 4.3, 5.2_
  - _Boundary: CliApplication, BuildCommandOptions_

- [x] 2.2 (P) プロジェクトルート解決を実装する
  - 明示されたプロジェクトディレクトリを優先し、省略時は現在ディレクトリから親方向に `kes.xml` を探索する。
  - 存在しない、アクセスできない、または `kes.xml` を発見できない場合はCLI診断として返す。
  - 完了時には、明示パス、上位探索、未検出ケースがそれぞれ成功または終了コード6相当の結果になる。
  - _Requirements: 1.2, 1.3, 2.2, 5.4_
  - _Boundary: ProjectRootResolver_

- [x] 2.3 (P) 最小 `kes.xml` 読み込みを実装する
  - 解決済みプロジェクトルートの `kes.xml` を読み、Project.Entry と標準パス設定を取得する。
  - XMLが読めない、壊れている、必須項目が欠けている場合は設定問題を識別できる診断にする。
  - 完了時には、有効設定からentryと各パスが取得でき、不正設定では非ゼロ扱いの診断が返る。
  - _Requirements: 2.1, 2.3, 2.4, 5.4_
  - _Boundary: ProjectConfigLoader_

- [x] 2.4 (P) `.kel` と参照スクリプトのファイル読込・構文解析を実装する
  - entry `.kel` と参照先スクリプトを読み込み、既存パーサで構文検査する。
  - ファイル欠落や読込失敗はファイル診断とファイル入出力ステージ失敗として扱う。
  - 字句解析または構文解析の失敗は、ファイル、行、列を持つ構文診断として保持する。
  - 完了時には、正常入力、欠落入力、不正文法入力の結果を同じ呼び出し形で区別できる。
  - _Requirements: 3.1, 3.2, 3.3, 3.4, 5.3, 5.4_
  - _Boundary: SourceFileParser_

- [x] 2.5 (P) `.kel` から参照スクリプトを抽出する
  - 解析済み `.kel` のオブジェクト木から `chapter` キーの文字列値または識別子値を探索する。
  - 参照パスは出現順を保ち、同一参照の重複解析を避ける。
  - 参照パスは拡張子やディレクトリを作り替えず、`.kel` に書かれた値を後続解決へ渡す。
  - 完了時には、ネストした `chapter` と重複参照を含む入力で、期待順の一意な参照リストが得られる。
  - _Requirements: 3.2_
  - _Boundary: KelScriptReferenceResolver_

- [x] 3. check-only検証フローを統合する
- [x] 3.1 プロジェクト解決からスクリプト解析までのステージ順序を統合する
  - プロジェクトルート解決、設定読み込み、entry `.kel` 解析、参照スクリプト解析を順に実行する。
  - 早い処理段階で失敗した場合は後続段階をスキップし、同一段階内の診断は順序を保って返す。
  - 完了時には、複数カテゴリの失敗候補がある入力でも、最も早い処理段階の終了コードが返る。
  - _Depends: 2.2, 2.3, 2.4, 2.5_
  - _Requirements: 1.1, 2.1, 2.4, 3.1, 3.2, 5.1, 5.3, 5.4, 5.5_

- [x] 3.2 CLIルート、診断出力、終了コードを接続する
  - 引数検証済みの `build --check-only` を統合済み検証フローへ渡す。
  - text と JSON Lines の選択に応じて、検証結果の診断を標準形式で出力する。
  - 完了時には、CLIアプリケーション呼び出しで標準出力または標準エラー出力、診断形式、終了コードをまとめて検証できる。
  - _Depends: 1.2, 2.1, 3.1_
  - _Requirements: 1.1, 1.4, 4.1, 4.2, 4.3, 4.4, 4.5, 5.1, 5.2, 5.3, 5.4_

- [x] 3.3 check-onlyの副作用禁止境界を保証する
  - check-only実行中は `.k`、manifest、診断ファイル、build/dist 出力を生成しない。
  - runtime起動やruntime入力準備に接続しない読み取り専用フローとして維持する。
  - 完了時には、既存成果物を含むプロジェクトで実行してもファイル一覧と内容が変化しない。
  - _Depends: 3.1_
  - _Requirements: 3.5, 6.1, 6.2, 6.3, 6.4_

- [x] 3.4 プロセスレベルの `kes build --check-only` 実行経路を確認する
  - ビルド済みCLIをプロセスとして起動し、明示プロジェクト指定と現在ディレクトリ探索の両方を検証する。
  - 成功、構文エラー、ファイル入出力エラー、コマンドラインエラーの終了コードをプロセス結果で固定する。
  - 完了時には、実際のコマンド実行に近いテストで標準出力、標準エラー出力、終了コードを確認できる。
  - _Depends: 3.2_
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 5.1, 5.2, 5.3, 5.4_

- [x] 4. 回帰テストと最終検証を追加する
- [x] 4.1 コアサービスの単体テストを追加する
  - 引数受付、プロジェクト探索、設定読込、参照抽出、ファイル解析、診断出力をサービス境界ごとに検証する。
  - 診断はレベル、コード、ファイル、行、列、メッセージを確認する。
  - 完了時には、各サービスの正常系と代表的な失敗系が自動テストで固定される。
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 2.1, 2.2, 2.3, 2.4, 3.1, 3.2, 3.3, 3.4, 4.1, 4.2, 4.3, 4.4, 5.2, 5.3, 5.4_

- [x] 4.2 check-only統合テストを追加する
  - 最小プロジェクト、entry欠落、`.kel` 構文不正、参照スクリプト構文不正、JSON Lines 出力を統合フローで検証する。
  - 成功時はエラー診断を出さず、失敗時は要求された終了コードと診断順序を確認する。
  - 完了時には、受け入れ条件に対応するCLI統合テストが `dotnet test` で実行できる。
  - _Requirements: 2.1, 2.2, 2.3, 2.4, 3.1, 3.2, 3.3, 3.4, 3.5, 4.1, 4.2, 4.3, 4.4, 4.5, 5.1, 5.3, 5.4, 5.5_

- [x] 4.3 成果物非生成と既存テストの回帰確認を行う
  - check-only前後で `.k`、manifest、build、dist の生成や更新がないことを自動テストで確認する。
  - 既存のlexer、parser、diagnostic formatterテストが新しいCLI経路の追加後も通ることを確認する。
  - 完了時には、関連テスト一式と差分の空白チェックが成功し、検証結果をPR本文へ転記できる。
