# Requirements Document

## Introduction

GitHub Issue #30 は、KoromoEventScript の作業開始地点となる `kes init` を CLI に追加し、ユーザーが最小 KES プロジェクトを即座に作成できるようにすることを求めている。現在は初期化コマンドが存在しないため、利用者は `kes.xml`、エントリ `.kel`、エントリ `.ke`、素材ディレクトリを手で用意しなければならず、最初のビルド確認までに不要な手作業が発生している。`kes init` は、生成直後に `kes build --check-only` へ進める最小構成を一貫して作成できる必要がある。

## Boundary Context

- **In scope**: `kes init` のコマンド受付、最小プロジェクト構成の生成、生成内容の整合、既存ファイルとの衝突時の安全な失敗、利用開始に必要な成功/失敗の案内。
- **Out of scope**: 対話式テンプレート選択、複数テンプレート対応、ランタイム向け素材の実体生成、高度なサンプルシナリオ生成、既存プロジェクトの移行支援。
- **Adjacent expectations**: 既存の `kes build --check-only`、`kes.xml` 設定形式、`.kel` 構文、`.ke` スクリプト構文、CLI 診断形式と終了コードの流儀に従う。

## Requirements

### Requirement 1: `kes init` コマンドで初期化を開始できる

**Objective:** CLI利用者として、`kes init` を実行して新しい KES プロジェクトの作成を開始したい。これにより、手作業なしで作業を始められる。

#### Acceptance Criteria

1. `kes init` が対象ディレクトリで実行されたとき、CLI はそのディレクトリに対するプロジェクト初期化を開始しなければならない。
2. プロジェクト初期化が開始されたとき、CLI は対象ディレクトリを生成対象ファイルおよびディレクトリのプロジェクトルートとして扱わなければならない。
3. `kes init` に対するコマンドライン引数が不正な場合、CLI はコマンドライン診断を報告し、非 0 の終了コードを返さなければならない。

### Requirement 2: 最小構成の KES プロジェクトを生成する

**Objective:** CLI利用者として、`kes init` に最小構成をまとめて生成してほしい。これにより、追加の手作業なしで最初の検証に進める。

#### Acceptance Criteria

1. `kes init` が正常終了したとき、CLI はプロジェクトルートに `kes.xml` を生成しなければならない。
2. `kes init` が正常終了したとき、CLI は初期化されたプロジェクト内にエントリ `.kel` ファイルを生成しなければならない。
3. `kes init` が正常終了したとき、CLI は生成した `.kel` から参照される少なくとも 1 つのエントリ `.ke` ファイルを生成しなければならない。
4. `kes init` が正常終了したとき、CLI は文書化された最小プロジェクト構成に必要な素材ディレクトリ構造を作成しなければならない。
5. `kes init` が正常終了したとき、CLI は生成されたすべてのファイル内のパスと名前がプロジェクト内で整合していることを保証しなければならない。

### Requirement 3: 生成直後のプロジェクトが検証可能である

**Objective:** CLI利用者として、生成した直後のプロジェクトをそのまま検証したい。これにより、初期化結果が正しいことをすぐ確認できる。

#### Acceptance Criteria

1. `kes init` によってプロジェクトが生成されたとき、生成された `kes.xml` は文書化されたプロジェクト設定規則に従って生成済みのエントリ `.kel` を参照しなければならない。
2. 生成されたエントリ `.kel` がイベントスクリプトを参照するとき、その参照パスは初期化されたプロジェクト内の生成済み `.ke` ファイルへ解決できなければならない。
3. `kes init` で生成されたプロジェクトに手動編集を加えず `kes build --check-only` を実行したとき、CLI は必須プロジェクトファイル不足を示す診断を報告せずに正常完了しなければならない。

### Requirement 4: 既存ファイルとの衝突を安全に扱う

**Objective:** CLI利用者として、`kes init` には既存内容を壊さずに失敗してほしい。これにより、誤って作業中のファイルを上書きせずに済む。

#### Acceptance Criteria

1. 対象ディレクトリに生成予定の最小プロジェクト構成で必要となるファイルまたはディレクトリがすでに存在する場合、CLI は衝突内容を特定する診断を報告し、既存内容を暗黙に上書きしてはならない。
2. 初期化中に必要なファイルまたはディレクトリを作成できない場合、CLI はファイルまたはディレクトリに関する診断を報告し、非 0 の終了コードを返さなければならない。
3. 初期化が完了前に失敗したとき、CLI はプロジェクト初期化成功として報告してはならない。

### Requirement 5: 利用開始に必要な結果を案内する

**Objective:** CLI利用者として、`kes init` の結果を分かりやすく表示してほしい。これにより、次に何をすればよいか迷わない。

#### Acceptance Criteria

1. `kes init` が正常終了したとき、CLI は対象ディレクトリに対するプロジェクト初期化が成功したことを報告しなければならない。
2. `kes init` が正常終了したとき、CLI は成功出力の中で生成されたプロジェクトルートを示さなければならない。
3. `kes init` が失敗したとき、CLI は他コマンドと同じ標準 CLI 診断形式で診断を報告しなければならない。
