# Requirements Document

## Introduction

GitHub Issue #30 は、KoromoEventScript の作業開始地点となる `kes init` を CLI に追加し、ユーザーが新しい KES プロジェクトを公開 CLI 仕様どおりに作成できるようにすることを求めている。現在は初期化コマンドが存在しないため、利用者は `kes.xml`、イベントファイル、素材配置先、ローカライズ配置先、ビルド出力先を手で用意しなければならず、最初の検証やビルド確認までに不要な手作業が発生している。`kes init` は、標準ディレクトリ構成と必要に応じたサンプルファイルを一貫して生成し、公開仕様に定義された `basic` / `empty` テンプレートと各オプションを正しく扱える必要がある。

## Boundary Context

- **In scope**: `kes init` のコマンド受付、`PROJECT_DIR` と `--name` / `--template` / `--force` / `--no-sample` の解釈、標準プロジェクト構成の生成、テンプレート差分、既存ファイルとの衝突時の安全な失敗、利用開始に必要な成功/失敗の案内。
- **Out of scope**: 対話式テンプレート選択、`basic` / `empty` 以外のテンプレート追加、ランタイム向け素材の実体生成、高度なサンプルシナリオ生成、既存プロジェクトの移行支援。
- **Adjacent expectations**: 既存の `kes build --check-only`、`kes.xml` 設定形式、`.kel` 構文、`.kc` スクリプト構文、CLI 診断形式と終了コードの流儀に従う。

## Requirements

### Requirement 1: `kes init` コマンドで初期化を開始できる

**Objective:** CLI利用者として、`kes init` を実行して新しい KES プロジェクトの作成を開始したい。これにより、手作業なしで作業を始められる。

#### Acceptance Criteria

1. `kes init` が対象ディレクトリで実行されたとき、CLI はそのディレクトリに対するプロジェクト初期化を開始しなければならない。
2. `PROJECT_DIR` が省略されたとき、CLI は現在のディレクトリをプロジェクトルートとして扱わなければならない。
3. プロジェクト初期化が開始されたとき、CLI は対象ディレクトリを生成対象ファイルおよびディレクトリのプロジェクトルートとして扱わなければならない。
4. `kes init` に対するコマンドライン引数が不正な場合、CLI はコマンドライン診断を報告し、非 0 の終了コードを返さなければならない。

### Requirement 2: `kes init` の公開オプションを解釈できる

**Objective:** CLI利用者として、公開仕様で定義された `kes init` オプションを使いたい。これにより、作成するプロジェクト名や初期内容を目的に合わせて制御できる。

#### Acceptance Criteria

1. `--name <NAME>` が指定されたとき、CLI は生成する `kes.xml` のプロジェクト名にその値を反映しなければならない。
2. `--name` が省略されたとき、CLI は公開仕様と整合する既定のプロジェクト名決定規則を適用しなければならない。
3. `--template <basic|empty>` が指定されたとき、CLI は指定されたテンプレートに対応する生成内容を選択しなければならない。
4. `--template` が省略されたとき、CLI は `basic` テンプレートとして振る舞わなければならない。
5. `--no-sample` が指定されたとき、CLI はサンプル `.kc` / `.kel` を生成してはならない。
6. `--force` が指定されたとき、CLI は公開仕様で許可された範囲の既存ファイル上書きを許可しなければならない。

### Requirement 3: 標準プロジェクト構成を生成する

**Objective:** CLI利用者として、公開仕様どおりの標準プロジェクト構成を自動生成してほしい。これにより、ディレクトリや設定ファイルを手作業でそろえずに済む。

#### Acceptance Criteria

1. `kes init` が正常終了したとき、CLI はプロジェクトルートに `kes.xml` を生成しなければならない。
2. `kes init` が正常終了したとき、CLI は `events/`、`assets/`、`locale/`、`build/`、`dist/` を含む標準ディレクトリ構成を生成しなければならない。
3. `kes init` が正常終了したとき、CLI は `assets/` 配下に公開仕様で定義された素材用サブディレクトリを生成しなければならない。
4. `basic` テンプレートが有効で、かつ `--no-sample` が指定されていないとき、CLI は `events/main.kel` と `events/chapter001.kc` を生成しなければならない。
5. 生成された `kes.xml`、ディレクトリ、サンプルファイルは、プロジェクト内で相互参照するパスと名前が整合していなければならない。

### Requirement 4: 生成直後のプロジェクトが公開仕様どおり利用可能である

**Objective:** CLI利用者として、生成したプロジェクトをすぐ次の作業へ進めたい。これにより、初期化結果が公開仕様どおり有効かをその場で確認できる。

#### Acceptance Criteria

1. `basic` テンプレートが有効で、かつ `--no-sample` が指定されていないとき、生成された `kes.xml` は `events/main.kel` をエントリとして参照しなければならない。
2. `basic` テンプレートが有効で、かつ `--no-sample` が指定されていないとき、生成された `events/main.kel` は生成済みの `events/chapter001.kc` を参照しなければならない。
3. `basic` テンプレートが有効で、かつ `--no-sample` が指定されていないとき、生成直後のプロジェクトに対する `kes build --check-only` は、必須ファイル不足を示す診断なしで正常完了しなければならない。

### Requirement 5: 既存ファイルとの衝突を公開仕様どおり扱う

**Objective:** CLI利用者として、`kes init` には既存内容を壊さずに失敗してほしい。これにより、誤って作業中のファイルを上書きせずに済む。

#### Acceptance Criteria

1. 生成対象のファイルまたはディレクトリがすでに存在し、かつ `--force` が指定されていない場合、CLI は衝突内容を特定する診断を報告し、既存内容を暗黙に上書きしてはならない。
2. `--force` が指定されている場合、CLI は公開仕様で上書きが許可された生成対象に対して初期化を継続できなければならない。
3. 初期化中に必要なファイルまたはディレクトリを作成または更新できない場合、CLI はファイルまたはディレクトリに関する診断を報告し、非 0 の終了コードを返さなければならない。
4. 初期化が完了前に失敗したとき、CLI はプロジェクト初期化成功として報告してはならない。

### Requirement 6: 利用開始に必要な結果を案内する

**Objective:** CLI利用者として、`kes init` の結果を分かりやすく表示してほしい。これにより、次に何をすればよいか迷わない。

#### Acceptance Criteria

1. `kes init` が正常終了したとき、CLI は対象ディレクトリに対するプロジェクト初期化が成功したことを報告しなければならない。
2. `kes init` が正常終了したとき、CLI は成功出力の中で生成されたプロジェクトルートを示さなければならない。
3. `kes init` が失敗したとき、CLI は他コマンドと同じ標準 CLI 診断形式で診断を報告しなければならない。
