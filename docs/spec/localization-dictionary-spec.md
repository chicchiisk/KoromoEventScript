# ローカライズ辞書仕様書

KoromoEventScript のローカライズ辞書は、翻訳作業用の交換フォーマットである。
本仕様では、`kes loc` が出力し、`kes build --loc <language-tag>` が入力として参照する `.csv` ファイル形式を定義する。

## 基本方針

- ローカライズ辞書は翻訳者が直接編集することを前提とする。
- 人間可読性と、表計算ソフトとの互換性を重視する。
- ランタイムはこの `.csv` を直接読み込まない。
- CLI は `.csv` と `.kc` を突き合わせて、対象言語向けの `.klib` を compile-time に生成する。

## ファイル形式

- 拡張子は `.csv` とする。
- 文字エンコーディングは UTF-8 with BOM とする。
- 改行コードの標準出力は CRLF とする。
- reader は CRLF と LF の両方を受け付けてよい。
- CSV のフィールド区切りはカンマ `,` とする。
- フィールドにカンマ、改行、ダブルクォートを含む場合は RFC 4180 相当の CSV エスケープを行う。

## 役割

ローカライズ辞書は、`.kc` に書かれた基準言語の本文と、各言語タグに対応する翻訳文を対応付ける。

- `tag` は `.kc` 側のローカライズタグと一致する安定キーである。
- `original` は基準言語の原文を保持する。
- 各言語タグ列は、その言語で実際に表示する翻訳文を保持する。
- `say` は翻訳支援用の補助列であり、ランタイム表示契約そのものではない。

ローカライズ辞書には、CLI が `.kc` から自動抽出する行と、利用者が手動で追加する行の両方を含めてよい。
手動追加行は、`localize.get` のような明示参照で利用する。

## カラム定義

ローカライズ辞書の先頭行はヘッダ行とし、少なくとも次のカラムをこの順序で含まなければならない。

| カラム名 | 必須 | 内容 |
|---|---|---|
| `tag` | 必須 | テキストタグ。`.kc` 中のタグと同じ文字列 |
| `say` | 必須 | 話者名。`say` 構文から抽出する翻訳支援用情報 |
| `original` | 必須 | 基準言語の原文テキスト |
| `<language_tag>` | 1列以上 | 言語タグごとの翻訳文 |

`<language_tag>` は任意の言語タグ名を表す動的カラムである。たとえば `ja`、`en`、`fr`、`en-US` などを使える。

## 言語タグ

- 言語タグカラム名は任意の英数字とハイフンを使えるものとし、`[0-9a-zA-Z-]` の範囲で構成する。
- 言語タグは自由に定義してよい。
- 相互運用性のため、RFC 5646 / BCP 47 に従うことを推奨する。
- タグは短いものを推奨する。たとえば日本語は通常 `ja-jp` より `ja` を推奨する。

## 各カラムの詳細

### `tag`

- `.kc` 中のタグと完全一致しなければならない。
- `#` を含めない内部 ID で保持する。
- ファイル内で一意でなければならない。
- `kes correct` により自動補完または書き戻しされたタグを基準とする。
- `kes correct` による自動補完タグは次の命名規則に従う。
  - `say` : `sy_<normalized-script-file-name>_<number>`
  - `nar` : `na_<normalized-script-file-name>_<number>`
  - `select-case` : `se_<normalized-script-file-name>_<number>`
- `<normalized-script-file-name>` は、拡張子を除いたスクリプトファイル名から空白を除去し、小文字化し、`_` 以外の記号類を除去した文字列である。
- `<number>` は 4 桁ゼロ埋めの連番であり、`0001` から開始する。`9999` を超える場合は `10000`、`10001` のように桁数を増やす。
- 同一 `.kc` ファイル内では、`say`、`nar`、`select-case` の3種類で番号空間を共有し、出現順の共通連番として採番する。

### `say`

- `say` 構文から抽出される話者名を入れる。
- `nar` など話者を持たない本文では空文字列としてよい。
- 翻訳者の文脈理解を助けるための列であり、翻訳キーではない。
- runtime は `say` 列を表示テキスト解決の主キーとして利用してはならない。

### `original`

- `.kc` に書かれた基準言語の原文をそのまま保持する。
- インラインマクロは加工せず保持する。
- `say` 本文、`nar` 本文、選択肢本文など、ローカライズ対象として抽出されたテキストを入れる。

### `<language_tag>`

- その言語で表示したい翻訳文を入れる。
- 改行、改ページ、インラインマクロ、制御記法などは `original` と同様に保持してよい。
- 未翻訳の場合は空文字列でよい。
- 同じタグに対する翻訳文は、対応する `original` の意味を保持することを期待する。

## 行の意味

1 行は 1 つのローカライズ対象テキストを表す。

CLI が自動抽出する対象には少なくとも次を含める。

- `say` 構文の本文
- `nar` 構文の本文
- `select` - `case` 構文の選択肢テキスト

加えて、利用者は任意の `tag` を持つ補助エントリを辞書へ手動で追加してよい。
この用途は、主人公名、組織名、地名、UI 固有語などをスクリプト中で変数化して参照したい場合を想定する。

例:

```csv
tag,say,original,ja,en
proper_name_hero,,乃愛,乃愛,Noah
```

このような補助エントリは `.kc` 側で `localize.get("proper_name_hero")` により参照できる。

## 例

```csv
tag,say,original,ja,en,fr
sy_prologue_0001,Hero,"旅はまだ続く","旅はまだ続く","The journey continues.","Le voyage continue."
na_prologue_0002,,"静かな森に足を踏み入れた。","静かな森に足を踏み入れた。","We stepped into the quiet forest.","Nous avons pénétré dans la forêt silencieuse."
se_prologue_0003,,街へ向かう,街へ向かう,Go to town,Aller en ville
```

## `kes loc` の更新規則

- 既存辞書がある場合、`kes loc` は既存の翻訳列を保持しつつ不足行と不足列を補う。
- `--locale` が指定された場合、既存辞書の言語タグ列に指定タグをマージする。
- 既存辞書に含まれる言語タグ列は、`--locale` 指定の有無にかかわらず保持する。
- `tag` が既存辞書に存在し、新しい抽出結果にも存在する場合、既存翻訳は引き継がれるべきである。

## 検証規則

CLI は少なくとも次を検証しなければならない。

- 必須カラム `tag`、`say`、`original` が存在すること
- `tag` が一意であること
- 言語タグカラム名が許可文字集合に従うこと
- `tag` が `.kc` / `.kel` から抽出されたローカライズ対象と整合すること

自動抽出対象に対応しない手動追加 `tag` は許可してよい。
ただし、その `tag` が `.kc` から `localize.get` などで参照された場合、build は対象辞書に当該 `tag` が存在することを検証しなければならない。

## 非目標

この仕様は翻訳用の交換フォーマットを定義する。
runtime 向けの実行形式は、build が生成するローカライズ済み `.klib` と、その配置を定義する CLI / runtime 仕様が所有する。
