# ADR

このディレクトリには、Architecture Decision Record を配置する。

ADR は、長期的に参照する設計判断と、その判断理由を記録するための文書である。
仕様そのものではなく、なぜその方針を採用したのかを残す。

## 目的

- 重要な設計判断を後から追跡できるようにする
- 代替案と採用理由を明文化する
- 将来の変更時に、過去の前提を確認しやすくする

## 置くべき内容

- レイヤ責務の分離方針
- 診断 ID やファイル形式などの永続的な設計ルール
- テスト戦略やスナップショット形式の採用判断
- 将来の実装に継続的な影響を与える判断

## 置かない方がよい内容

- 単なる作業メモ
- 一時的な調査ログ
- Issue 限定で閉じる細かな実装手順

## 運用

- 1 つの判断につき 1 ファイルを作る
- ファイル名は `0001-short-title.md` のように連番と要約を使う
- 新規作成時は [0000-template.md](0000-template.md) を複製して使う
- 内容は原則として日本語で記述する

## ステータス例

- 提案中
- 採用
- 置換済み
- 廃止
