# VM内部オブジェクトを整数ハンドルで参照する

- ADR: 0006
- ステータス: 採用
- 日付: 2026-07-20
- 関連 Issue: 性能改善計画 5
- 関連仕様: `docs/spec/k-intermediate-representation-spec.md`、`docs/spec/unity-runtime-spec.md`

## 背景

配列とクラスインスタンスは、`array:123` や `instance:45` の文字列を生成し、命令ごとに文字列辞書で検索していた。配列アクセスは数値計算の内側で大量に実行されるため、文字列の生成、ハッシュ計算、辞書検索が不要な負荷になる。

一方、actor参照のようにホストやmanifestとの境界を越える識別子は、公開契約として文字列を維持する必要がある。

## 決定

VMが所有する配列とクラスインスタンスは、`RuntimeReferenceKind` と非負の整数 `ObjectHandle` で参照する。オブジェクトストアは種別ごとの配列を持ち、ハンドルを添字として直接アクセスする。

ホストが所有する外部参照は `RuntimeReferenceKind.External` と文字列 `ReferenceId` を使用し、内部ハンドルとは混在させない。

## 検討した代替案

### 文字列辞書を継続する

デバッグ時には読みやすいが、ホットパスの検索コストと一時文字列を除去できないため採用しない。

### 全参照を整数化する

actorやassetの公開識別子を別表へ変換する必要があり、ホストAPIとセーブデータの互換性を複雑にするため採用しない。

## 判断理由

- 配列アクセスを添字境界確認と配列参照だけで処理できる。
- 参照種別を値に保持するため、配列とインスタンスの取り違えを検出できる。
- 外部参照の既存契約を維持できる。
- 後続の型特化配列を同じハンドル表に格納できる。

## 影響

- `RuntimeValue` の参照値には参照種別とハンドルが追加される。
- 内部オブジェクトの表示用文字列は恒久IDとして扱わない。
- オブジェクト破棄後のスロットは再利用せず、実行セッション中の古いハンドルが別オブジェクトを指さないようにする。
- call frame対応snapshotでは、内部オブジェクト表もハンドルを保ったまま保存・復元する必要がある。

## フォローアップ

性能改善計画6で、配列ハンドルが指す格納形式を要素型ごとの専用配列へ変更する。
