# CLI ビルドは当面フルビルドのみとする

- ADR: 0001
- ステータス: 採用
- 日付: 2026-07-04
- 関連 Issue:
- 関連仕様: `docs/spec/cli-tool-spec.md`

## 背景

CLI 仕様には `kes build --no-incremental` が定義されていたが、現行実装ではオプションを解析して `BuildCommandOptions` へ渡すだけで、`BuildPipelineService` では利用していなかった。

初期 MVP の段階では、入力ファイル数と成果物規模はまだ小さく、インクリメンタルビルドのキャッシュ設計、依存関係追跡、無効化条件、検証テストを先に持つより、常にフルビルドする方が仕様と実装を単純に保てる。

## 決定

`kes build` は当面、常にフルビルドとして実行する。

`--no-incremental` は公開 CLI 仕様から削除し、実装でも受け付けない。指定された場合は他の未対応オプションと同様にコマンドライン引数エラーとして扱う。

## 検討した代替案

### 案 1: `--no-incremental` を残して no-op として扱う

既存のコマンドライン互換性は保てるが、利用者にインクリメンタルビルドが存在するかのような誤解を与える。仕様と実装の差分も残るため採用しない。

### 案 2: インクリメンタルビルドを今すぐ実装する

将来的な性能改善には有効だが、現時点では必要性が低い。依存関係追跡やキャッシュ形式の設計判断が増え、初期 MVP の実装範囲を広げるため採用しない。

## 判断理由

- 仕様と実装を一致させられる。
- ビルド処理の挙動を単純に保てる。
- キャッシュ不整合による古い成果物の混入を避けられる。
- インクリメンタルビルドが必要になった時点で、性能要件とキャッシュ設計を改めて仕様化できる。

## 影響

- `docs/spec/cli-tool-spec.md` から `--no-incremental` を削除する。
- `BuildCommandOptions` から `NoIncremental` を削除する。
- `kes build --no-incremental` は `KES9001` のコマンドライン引数エラーになる。
- 将来インクリメンタルビルドを導入する場合は、新しい仕様、受け入れ条件、キャッシュ無効化ルール、テストを追加する。

## フォローアップ

ビルド時間が開発体験または CI 時間の問題になった場合に、インクリメンタルビルド導入の Issue を作成する。
